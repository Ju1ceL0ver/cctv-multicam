# Локальный опыт: видимость и восстановление маски

500 исходных масок учителя и изображений с запасом вокруг человека. Набор выбран
по разным дням, не больше одного человека из одного исходного кадра. Это примеры
cam1 из существующего набора inout, а не 500 независимо проверенных треков.
Соседние кадры в этой первой версии не экспортированы.

Запуск разметчика на Mac из корня репозитория:

```sh
python3 amodal_lab/serve.py
```

Открыть http://127.0.0.1:8767 . Обводка переключается; весь исходный кадр раскрывается.
Отметить видимость и качество **видимой** маски. Плохие маски, край кадра и
неуверенные ответы исключаются из первого обучения. Ответы сохраняются сразу
в `data/labels.json`, история — `data/history.jsonl`. Можно вернуться и исправить.
Клавиши 1–5 выбирают видимость, Enter сохраняет после выбора качества.

Только после ручной проверки:

```sh
python3 amodal_lab/train.py --task visibility --val-day 20260918
python3 amodal_lab/train.py --task completion --val-day 20260918
```

День проверки можно выбрать другой. Требуется ≥20 train и ≥5 val допущенных
масок; для видимости — оба класса по обе стороны. Все примеры выбранного дня
исключаются из обучения. Совпадение людей между днями пока не проверено;
эта проверка не доказывает обобщение на новых людей.

Маленькая модель принимает RGB + видимую бинарную маску 96×160. Восстановление
учится **только** на `full` + `good`: искусственные столбы, стойки, верхние
перекрытия и приблизительный силуэт человека закрывают одновременно RGB и
маску. Цель — исходная подтверждённая маска. На проверке перекрытия фиксированы
по ID; отчёт содержит IoU скрытой области и полной маски. Без достраивания IoU
скрытой области равен 0. Это оценка на синтетических перекрытиях, а не на
настоящих скрытых ногах. Обучение видимости использует реальные ответы full /
occluded. Модели и точный список примеров записываются в `runs/<task>/`.

Обучение на MPS доступно через текущий python3. При необходимости `--device cpu`.
В боевую систему ничего не подключается. Признаки последовательности кадров,
уверенность восстановленной формы и проверка реальных треков — следующий этап.

## Исправление масок и клавиатура

1–5 — видимость; Q/W/E — качество; Enter — сохранить и перейти дальше.
←/→ — предыдущий/следующий пример, O — обводка, F — исходный кадр.
M — редактор; B — кисть добавления; X — стирание; [/] — размер кисти;
Z/Y или Cmd+Z / Cmd+Shift+Z — отмена и повтор. В редакторе стрелки двигают
курсор кисти (Shift — быстрее), пробел наносит мазок; Esc возвращает навигацию.
Также доступны рисование мышью и кнопки всех основных действий.

Исправляйте **видимую** часть человека: скрытые ноги здесь дорисовывать не нужно.
После исправления отметьте качество получившейся маски. Полная хорошая маска
может войти в обучение восстановления; закрытая хорошая — в обучение видимости.
Правки и ответы при переходах хранятся в памяти вкладки; Enter сохраняет на диск.
Закрытие/перезагрузка при несохранённых изменениях вызывает предупреждение.

Сервер принимает PNG исходного размера, только 0/255, запрещает пустую хорошую
маску. Исправления сохраняются отдельно в `data/edited/` с SHA256 в имени;
исходные файлы не перезаписываются, история хранит ссылки на версии. Обучение и
предсказание используют последнюю исправленную маску, если она есть. В split.json
сохраняются пути и SHA256 всех масок. Метки прежней версии разметчика совместимы.

## Расширенные аугментации

`augment.py`: 13 семейств перекрытий — один/два столба, стойка, верхняя область,
4 края кадра, диагональ, прямоугольник, составной силуэт соседа, несколько объектов,
неровный многоугольник. Скрывается примерно 6–90% целевой маски, сохраняется
видимый фрагмент. Препятствия получают плоский цвет, шум, полосы либо текстуру
из того же кропа; края — тёмное заполнение. Это симуляция недостающих пикселей
в фиксированном холсте, не восстановление за пределами изображения.

Совместно преобразуются RGB и целевая маска: отражение, уменьшение и сдвиг,
сохраняющие исходный полный силуэт внутри холста. Яркость, цвет, шум и размытие
меняют только RGB. Маски остаются бинарными. Предсказанная скрытая форма —
гипотеза; новая ручная амодальная разметка автоматически не возникает.

```sh
python3 amodal_lab/train.py --task completion --val-day 20260918 --device mps --epochs 30 --augment rich --repeat 4 --run-name completion_rich --labels amodal_lab/runs/completion/labels_snapshot.json
python3 amodal_lab/evaluate_completion.py --run-name completion_rich
python3 amodal_lab/compare_augmentations.py
```

Повтор 4 означает четыре случайных варианта каждого train-примера за эпоху.
Используется snapshot исходных ответов для сравнения с первой моделью; новые
ручные ответы в этот прогон не добавляются. Старые результаты сохраняются.
Validation при выборе эпохи остаётся исходным; дополнительное сравнение
обеих моделей по 13 семействам фиксировано по ID+типу. Это всё ещё validation
на синтетике, не доказательство качества на настоящих перекрытиях. В новом
прогоне также больше шагов обучения, поэтому разницу нельзя приписать только
разнообразию аугментаций без отдельного опыта с равным числом шагов.

## Вход только по структуре маски

`--input-mode mask`: на вход сети подаётся один канал бинарного силуэта, RGB
полностью исключён. Для классификации можно добавить `--spatial --balanced`:
пространственное объединение признаков 5×3 вместо среднего по всей маске,
вес класса закрытых из train. Восстановление также поддерживает rich-аугментации.
В этом режиме используются заполненные бинарные маски, сохраняющие и контур,
и внутреннюю область. Только линию контура отдельным опытом пока не проверяли.
`predict.py` читает конфигурацию checkpoint и выбирает правильный вход.

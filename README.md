# cctv-multicam

Следим за покупателем от входа до выхода по двум камерам магазина напольных покрытий и кладём его путь
на план зала. Калибровка — из самих записей: ни маркеров, ни рулетки на объекте.

Съёмка: две камеры 2560×1440 @ 25 fps над торговым залом (`cam1` ближе ко входу, `cam2` в глубине).
Тяжёлые модели работают на машине с RTX 3060; код здесь, данные — нет.

## Как устроен конвейер

| шаг | файл | что делает |
|---|---|---|
| сырая запись | `jobs/raw_recorder.py` | `ffmpeg -c copy` с RTSP, 15-минутные сегменты, без декодирования |
| сегментация | `multicam/detect_raw.py` | yolo26x-seg @1536 за один проход: рамки, маски, точки ступни и головы, цвет одежды |
| внешность | `multicam/embed_clip.py` | ReID-дескрипторы OSNet-AIN x1.0 на каждую детекцию |
| синхронизация | `multicam/sync_estimate.py` | сдвиг времени между камерами по идущим людям |
| геометрия | `multicam/person3d.py` | человек как вертикальный отрезок: ступня на полу, рост из пары ступня-голова |
| трекинг | `multicam/imtrack.py` | по кадрам в пикселях (ByteTrack-подобный) с учётом внешности |
| склейка | `multicam/fusion2.py` | кластеризация кусков в людей, визиты по линии двери |
| проверка | `multicam/score_config.py`, `eval_ids.py` | точность по ручному эталону |
| разметка | `multicam/label_pieces.py` | веб-страница: «этот человек уже был или новый» |

Калибровка камер по самому залу: `multicam/calib_joint_k.py` (швы плитки + вертикали + отвесные линии),
`multicam/plumb.py` (дисторсия), `multicam/reg_appearance.py` и `fit_floor_map.py` (совмещение полов двух камер).

## Что измерено

На клипе 10:37–10:46 (9.5 минут, размечен вручную по кускам треков):

| | |
|---|---|
| доля «один человек — один номер», взвешенная | 0.705 |
| детекций под номером, который делят двое | 3.3% |
| короткие прохожие в галерее ТЦ | 0.95–1.00 |
| двое покупателей, идущих вплотную 8 минут | 0.76 и 0.58 |

Визит «вход → зал → выход» собирается целиком по обеим камерам.

Способность отличить человека по внешности (AUC, внутри камеры / между камерами):
средний цвет одежды **0.84 / 0.78**, OSNet x0.25 **0.95 / 0.93**, OSNet-AIN x1.0 **0.99 / 0.99**.

## Грабли, проверенные цифрами

- **Записи двух камер не синхронны**: сдвиг ~4.3 с, свой после каждого перезапуска рекордера (ffmpeg
  подключается к каждой камере со своей задержкой). Без поправки склейка между камерами не работает.
- **Маски внутри дескриптора внешности не помогают** (0.987 против 0.990): сеть обучена на обычных кропах.
  Маски полезны для глаза в разметчике и для отбора чистых кадров.
- **Способ связывания групп важнее порога**: по ближайшей паре десяток прохожих слипается в одного,
  по самой дальней рассыпаются настоящие люди; работает средняя связность. Порог плоский на 0.22–0.40.
- **Правило «в одно время в разных местах — разные люди» между камерами вредит** (0.70 → 0.49): точность
  совмещения полов ~0.4 м p90 с хвостами до 1.4 м.
- **Записи из боевого пайплайна идут на 12 fps**, хотя помечены как 25: рекордер получает только те кадры,
  которые успел обработать главный цикл. Для трекинга нужна сырая запись.

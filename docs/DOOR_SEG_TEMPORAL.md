# Экспериментальные отпечаток и память (10.10.2026)

Подготовлены по просьбе владельца во время переноса данных в Colab. В текущий
`doorseg_c_background` не включены: он продолжает исходную архитектуру с
исправленной датой фона. Новое обучение и переключение боевой двери не запущены.

`multicam/door_seg_temporal.py`: ConvGRU с 48 каналами памяти на stride16,
остаток в P3 с нулевой начальной проекцией и 64-мерный отпечаток на stride8.
Нулевая проекция сохраняет исходные признаки; память начинает получать
градиент сегментации после изменения этой проекции. Отпечаток сразу получает
свой контрастивный сигнал. До обучения он не годится для склейки.

Память принадлежит каждому месту батча и конкретной записи/камере/сессии.
Смена источника, разрыв последовательности, формы или типа тензора сбрасывает
соответствующую память. Во время inference состояние detached; обучение
распространяет градиент через ограниченную последовательность. Оно не входит
в checkpoint, не переносится между посетителями разных записей.

Отпечаток усредняется по маске человека и нормализуется. TRAIN ID-карта
следует существующему перекрытию масок; inference принимает независимые маски
и сохраняет их перекрытия. Пустые/нулевые векторы помечаются непригодными.
Исходные пять полей детекции/маски/смещений не изменены.

`multicam/door_seg_sequence.py` собирает соседние четыре или более кадров
одной сессии с одним seek и общим кэшем контекста. Яркость RGB и фона одинакова
внутри последовательности. Источники допускаются только из TRAIN manifest.
Идентичности берутся из существующих пространственных/owner связей, без
добавления склеек по внешности. Учитель всё ещё может ошибаться в личности.

Положительная пара — один ID в разные моменты той же записи/камеры/сессии.
Отрицательная — разные ID, одновременно видимые там же. Неподтверждённые
отношения между разными записями и непересекающимися треками не считаются
отрицательными. Для полезного контрастивного anchor нужны оба типа пары.

`DoorSegTemporal.prepare_frame(streams, ticks, retain_graph=...)` обязателен
перед каждым YOLO forward. Это блокирует случайный запуск старого shuffled
trainer/evaluator с неподходящей памятью. `sequence_loss` объединяет исходную
сегментацию/смещения и контрастивный loss, выполняет ordered unroll, возвращает
дифференцируемый loss и очищает память между последовательностями.

Старые веса загружаются с начальной памятью/отпечатком, новые checkpoints
сохраняют обе головы и описание архитектуры. Перед настоящим обучением нужен
отдельный sequence training loop с существующими finite/rejected/plateau
защитами и sequence validation. Моменты старого optimizer нужно перенести
только для прежних параметров, для новых создать пустые состояния; старый
optimizer нельзя загрузить в расширенную группу без такого переноса.
TEST10 не использовать для обучения, порогов или выбора новой головы.

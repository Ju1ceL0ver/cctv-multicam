# Готовый бинарный классификатор камеры 1

`inside_outside.py` + `inside_outside.pkl`. Зависимости: numpy, scipy, opencv-python, scikit-learn. Модель ExtraTrees, 32 дерева, 140 КБ, CPU; MPS не требуется.

```python
from inside_outside import InsideOutside
import cv2

model = InsideOutside(threshold=0.8)
rgb = cv2.cvtColor(cv2.imread('frame.jpg'), cv2.COLOR_BGR2RGB)
mask = cv2.imread('person.png', cv2.IMREAD_GRAYSCALE)  # только один человек
result = model.predict_rgb(rgb, mask)
print(result)  # label, confidence, uncertain, p_inside
```

При интеграции лучше передавать исходные `box` и `foot` трекера в пикселях кадра; `floor_px` — исходное расстояние до маски пола на масштабе 1280×720. Без них геометрия вычисляется по видимой маске и может отличаться при перекрытиях. Использовать только исходный ракурс камеры 1.

Проверка с исключением целого дня из обучения: 1376/1391 = 98,92%, 15 ошибок. Число деревьев выбрано по этой же проверке: это диагностическая оценка, не новый независимый тест. Финальный файл обучен на всех 1391 определённых примерах. 190 примеров «в проёме» и 47 «не понять» исключены. Метрика не распространяется на них.

На текущем Маке: около 7,7 мс на подготовленном примере, около 15 мс на вызов RGB+маска для одного человека; сегментация и чтение видео в это время не входят. Проверено точное совпадение признаков с исходным экспортом на 96 примерах (максимальная разница 0).

`uncertain` — порог оценки леса, НЕ классификация «в проёме» и НЕ гарантия обнаружения сложных примеров. При пороге 0,8 на определённых классах покрытие 96,55%, точность уверенных ответов 99,48%. Показатели для исходных примеров «в проёме» отдельно в `binary_doorway_report.json`. Для сохранения всех важных примеров следует либо оставить настоящий третий класс, либо отдельно разметить сторону каждого пограничного примера по явному правилу пересечения двери. Сам бинарный модуль этого не решает.

Воспроизведение: `python package_binary.py`; проверка уверенности на пограничных примерах: `python check_binary_doorway.py`.

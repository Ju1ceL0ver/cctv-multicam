## 5. Зоны владельца и правила стороны

`data/door_v2/door_lines_owner.json` (рисуются в `/doorside`: `K` линия, `G` область, точки тянутся мышью):

нет пикселя → никогда не «внутри»; бустинг по геометрии — только где правила молчат, голос при уверенности ≥ 0.6, смена стороны трека, событие только при касании проёма за 2 с, наследование стороны нового трека
только при перекрытии рамок ≥ 0.3, «вышел-вернулся» за 3 с не считается. Плакат: маска ≥ 65 % в рамке стойки
(514,35–559,158 на 1280×720) отбрасывается до трекера.

## 7. Правила работы

- Никогда не убивать `python.exe` по имени — только проверенный PID (`taskkill /PID … /F`, с `/T` только для своих деревьев).
- Не трогать без слова владельца: CRM и её формат, `keeper_plan.json`, `side_final.json`, разметку владельца,
  чужие программы на машине (3ds Max, Photoshop сотрудницы).

  прямому слову владельца. Тестовые отрезки в обучение не брать.
- Перед заменой файлов на машине — копия в `data/quality_backups/<дата>_<что>/`, после заливки — `py_compile`.
- Мерить, а не верить: каждое изменение — цифрой на эталоне владельца; не подбирать на test.
- Новые результаты — коротким разделом в `docs/AGENTS_HISTORY.md`, а сюда — только если меняется текущее состояние.

## 8. Следующий этап (план 14.10.2026): визиты покупателей и взаимодействия с сотрудниками

Цель: на каждый визит от входа до выхода — гладкая траектория по плану зала в метрах (время, x, y; рост, скорость,
зоны и время у стоек), взаимодействия с сотрудниками (кто, начало, конец, длительность, где) и видео «камера следит
за человеком» (вырезка с фоном). Порядок работ:
1. **На записях, не в бою:** треки (учитель SAM 3.1 / doorseg_c), склейка внутри камеры (место+время+внешность
   TransReID/CSCI) и между камерами (совмещение полов, медиана 0.19 м), сотрудники — галерея дня.
2. **Координаты:** точка пола по ногам; ноги закрыты — по голове и росту человека (рост — медиана по кадрам с видимыми
   ногами; «голова→ноги» уже есть в `zone_lab/lab2.py`). Калман с пределом скорости ~2.5 м/с и отсевом выбросов +
   сглаживание назад (задержка допустима); две камеры — взвешенно по уверенности.
3. **Взаимодействие (черновое правило, проверить на разметке):** покупатель и сотрудник ближе ~1.2 м дольше ~10 с,
   оба почти стоят.
4. **Видео визита:** сглаженная рамка ~2 роста с камеры, где лучше видно; MP4 целиком (~3–6 МБ на визит 360×480) +
   GIF-превью 10–20 с; кольцевой буфер кадров обеих камер на время визита.
5. **Хранение:** `data/visits/<день>/<id>.json` + `.mp4` + `.gif` (~0.5 ГБ/день при ~100 визитах).
6. **Проверка:** страница «визит целиком» для владельца (полнота, чистота, взаимодействия); цифра — доля полностью
   правильных визитов, полнота/точность взаимодействий.
7. Затем камера 2 вживую (~40 мс/кадр на камеру) и сборка визитов в живой системе.
Решения владельца (14.10): взаимодействие — ближе ~1.2 м дольше ~10 с, оба почти стоят (проверить на разметке);
видео — MP4 целиком + GIF-превью 10–20 с; хранить 30 дней (~15 ГБ); видео только покупателей.
